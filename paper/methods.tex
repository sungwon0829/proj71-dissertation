\section{Methods}
\label{sec:methods}

\subsection{Base model, adapter, and environment}
\label{sec:methods:base}

All arms derive from a single base model, \texttt{Qwen2.5-7B-Instruct}
\citep{qwen2024qwen25}, pinned to snapshot
\texttt{a09a35458c702b33eeacc393d103063234e8bc28}. The generation harness asserts that the
resolved snapshot matches this hash, and the scoring harness re-hashes the adapter it is
scoring and fails hard on a mismatch, so a silent model or checkpoint swap cannot enter a
result. All models are loaded from a local cache with network fetching disabled.

Every trained arm uses one Low-Rank Adaptation (LoRA) adapter configuration
\citep{hu2022lora}: rank $r=32$, $\alpha=64$, dropout $0.05$, applied to all attention
and multi-layer perceptron (MLP) projections
(\texttt{q\_proj}, \texttt{k\_proj}, \texttt{v\_proj}, \texttt{o\_proj},
\texttt{gate\_proj}, \texttt{up\_proj}, \texttt{down\_proj}), no bias adaptation. This
gives 80{,}740{,}352 trainable parameters against 7{,}696{,}356{,}864 total ($1.049\%$).
The configuration is identical for B1, B2, T and T\_ctrl; the training script compares
the adapter block of the running configuration against the supervised fine-tuning (SFT)
configuration at start-up and refuses to run if they differ. Numerical precision,
sequence length, batching and optimiser settings are in Appendix~\ref{app:hparams}.

We ran on one RTX PRO 6000 Blackwell (96\,GB) under native Windows Server 2025, with
PyTorch 2.11.0+cu128, transformers 5.14.1, TRL 1.9.0 and PEFT 0.19.1. Attention used
the scaled dot-product (SDPA) implementation; we used neither flash-attention,
bitsandbytes, nor vLLM, because none is reliable on this platform. Consequently all
arms use LoRA rather than full fine-tuning or QLoRA, and all batch generation runs
through \texttt{transformers}. Every script takes \texttt{--seed} and sets the Python,
NumPy and PyTorch seeds; the seed is written into the output directory name.

\subsection{Supervised fine-tuning: the B1 arm}
\label{sec:methods:sft}

B1 is the shared starting point for every preference-trained arm. We fine-tuned the
base model on therapy-style dialogue drawn from two public corpora: ESConv
\citep{liu2021esconv}, train split only (910 conversations; the 195-dialogue validation
and 195-dialogue test splits were held out and never trained on), and CounselChat
\citep{bertagnolli2020counselchat} (2{,}775 rows).

We parsed each ESConv row's JSON \texttt{text} field, mapped \texttt{usr}/\texttt{sys}
speakers to \texttt{user}/\texttt{assistant}, merged consecutive same-speaker turns, and
dropped leading assistant turns so that every conversation begins with a user message.
All 910 conversations survived; none was empty. For CounselChat we formed the user turn
from \texttt{questionTitle} followed by \texttt{questionText} and the assistant turn from
\texttt{answerText}. We dropped 26 rows whose \texttt{answerText} was empty, whitespace
or null, counting and listing them rather than skipping them silently, leaving 2{,}749.
CounselChat contains multiple therapist answers to the same question, so we deduplicated
to at most two answers per \texttt{questionID}, ranked by upvotes then views with ties
broken by stable sort on the original row order; this reduced 2{,}749 rows to 1{,}395.
Merging and deterministically shuffling the two sources gave
\texttt{sft\_train.jsonl}, 2{,}305 conversations. A mojibake audit found zero corrupted
characters in either corpus before or after \texttt{ftfy} repair; the replacement glyphs
visible in terminal output were correctly encoded U+2019 apostrophes that the console
font could not render, so no rows were dropped or altered on that basis.

Every conversation carries the same pinned system prompt, stored byte-for-byte in
\texttt{configs/system\_prompt.txt} and read by both training and evaluation:

\begin{quote}
\itshape You are a supportive, empathetic counsellor. Listen carefully, respond with
warmth and respect, and help the person explore their feelings and possible next steps.
\end{quote}

\paragraph{Assistant-only loss required replacing the chat template.} The stock
Qwen2.5-7B-Instruct chat template contains no \texttt{\{\% generation \%\}} markers.
Calling \texttt{apply\_chat\_template(..., return\_assistant\_tokens\_mask=True)} on it
emits a warning but does not raise: it returns an all-zero assistant mask, so
assistant-only loss silently degrades to no loss at all. We therefore wrote our own
template, \texttt{configs/qwen25\_chat\_template\_generation.jinja}, which renders
byte-identical text to the stock template (verified on a five-message conversation) but
wraps assistant content, the closing \texttt{<|im\_end|>} and the trailing newline in a
generation block. We verified masking empirically rather than by assumption: we pulled
one real collated batch from the trainer's own dataloader, decoded it token by token,
and dumped span-level \textsc{masked}/\textsc{trained} summaries. System messages, user
turns, the \texttt{<|im\_start|>assistant} scaffolding and end-of-sequence padding are
masked; assistant content plus \texttt{<|im\_end|>} plus the trailing newline is trained.
The training script asserts at least one trained span exists and that the first token of
the batch is masked, and aborts otherwise. We re-ran this verification from scratch on
the rescrubbed data (Section~\ref{sec:methods:scrub}) rather than assuming it carried
over.

We enforced zero truncation instead of packing: one example is one sequence, and the
script asserts before training that no tokenised example exceeds the 4{,}096-token limit
(maximum observed 2{,}619). Training ran for 3 epochs at effective batch size 16
(per-device batch 2, gradient accumulation 8, gradient checkpointing enabled), 435
optimiser steps, learning rate $1\times10^{-4}$ with cosine schedule.

\paragraph{Checkpoint selection.} We fixed the selection rule before training: score
held-out ESConv validation loss at each epoch checkpoint and select checkpoint-290
(epoch 2) if its loss is below that of checkpoint-435, otherwise checkpoint-435. Loss is
token-weighted mean assistant-only cross-entropy over all 60{,}701 scored tokens in the
195 validation dialogues, computed with the same template, the same system prompt and
the same masking used in training. The observed curve was
$2.1434 \rightarrow \mathbf{2.1413} \rightarrow 2.1714$ across checkpoints
145/290/435, so the rule selected \textbf{checkpoint-290}. The base model with no
adapter scored $4.6599$ on the same set, a 54\% relative reduction. We report that
figure only as a sanity check that SFT did something in the intended direction: it
measures next-token fit to ESConv crowdworker supporter turns, and much of the drop is
register adaptation (long structured prose to short conversational turns), not evidence
of better support.

\paragraph{Two B1 behaviours we measured and did not train away.} B1 produces markedly
shorter responses than the base model (median 97 characters on the frozen evaluation
suite against 1{,}118 for the base model; 73 characters on \texttt{crisis\_adjacent};
measured on the pre-scrub checkpoint, before the retrain of
Section~\ref{sec:methods:scrub}, which altered 70 of 2{,}749 answers and left the corpus
length distribution unchanged). We investigated this as a possible training fault, because
B2 and T would inherit it. ESConv assistant turns are 88\% of all training turn instances
(10{,}191 of 11{,}586) with a median of 95 characters, so B1's median sits on the corpus
median, and 36.6\% of ESConv assistant turns are 73 characters or shorter, so the crisis
median is not a tail value. Regenerating on
checkpoint-435 gave an indistinguishable median (83 against 80 characters), so terseness
does not depend on the checkpoint selected. We ruled out token-budget truncation,
premature end-of-sequence, and template artefacts. We therefore treat brevity as a
faithful property of the arm and did not retrain. B1 also invents first-person life
history it cannot have (for example, claiming to have overcome a fear of flying over
three years), a behaviour the base model does not exhibit and that SFT on peer-support
dialogue introduced. Neither behaviour is scored by any metric in this paper; we record
both here because they are inherited identically by every downstream arm.

\subsection{Data-provenance scrub of CounselChat}
\label{sec:methods:scrub}

CounselChat is a scrape of a public professional forum and is not anonymised: therapist
names, credentials, personal telephone numbers and practice URLs appear inside answer
text. During blind inspection of B1 generations on the frozen suite we found B1
completing a crisis-adjacent prompt with a real clinician's name and post-nominal
credentials, reproduced verbatim from a signature block in the training data. We treat
this as a privacy defect rather than a data-quality footnote, and we report it because
no metric in this paper would have surfaced it.

We voided every artefact downstream of the affected data --- the first B1 checkpoint and
the first B2 run --- scrubbed the corpus, and retrained from scratch. The scrub uses
CounselChat's own \texttt{therapistInfo} and \texttt{therapistURL} columns as per-row
ground truth and removes each answer's \emph{own} author identity only; a therapist's
name is never removed from a different therapist's answer. Name derivation splits the
fused \texttt{Name}+tagline field at a lowercase-to-uppercase boundary of at least three
characters, cuts at the first comma, strips titles, and cross-checks the derived first
and last name against the URL slug up to the first credential token. Of 437 distinct
therapists in the raw split (429 surviving the empty-answer drop), 399 names resolved
through the primary heuristic, 23 through a URL fallback, and 5 through documented
manual overrides; one business account and one therapist who signs with a bare initial
were excluded from name scrubbing rather than matched with a regex known to over-fire.
Telephone-number removal is context-gated: a number is kept if crisis or hotline language
appears within 80 characters before or 130 characters after it, because a blind strip
would have deleted crisis resources from a safety-focused corpus. URL removal fires only
when the therapist self-declared the URL, when the host contains their own name, or when
the URL directly follows a possessive reference to their own practice.

\paragraph{What was removed, and the verification.} The scrub removed name and
credentials from 70 answers, 32 personal telephone numbers and 23 practice URLs; a
corpus-wide scan found zero email addresses, so no email rule was written. Content was
preserved: median answer length was 779 characters before and after, no answer lost more
than 20\% of its length, and no answer was emptied. Row counts were unchanged
(910 / 1{,}395 / 2{,}305). Verification has two layers. A same-row hard gate re-runs each
row's own name pattern against its own scrubbed answer and aborts the run on any match;
it never fired on the shipped output. A corpus-wide sweep then checks every known
therapist's name pattern against every answer, and returned exactly one hit --- the
string ``Fred Rogers'' inside a \emph{different} therapist's answer, quoting the
television presenter. That is a name collision with a public figure, not a contributor
identity, and mangling it would violate the do-not-over-scrub requirement. ESConv was
confirmed unaffected by direct schema inspection: it has no author, credential or
contact fields at all. Two independent runs produced byte-identical outputs.

After retraining, we regenerated the item that triggered the incident and grepped a
canonical list of 427 distinct therapist full names --- derived by the scrub's own name
function rather than a separately maintained list --- against that generation and all 16
sanity generations. Full-name matches: zero. One surname-only match resolved on
inspection to an ordinary English word inside a user prompt.

\paragraph{Residual limitation.} A small number of practice URLs that use a branded name
unrelated to the therapist's own name, and that were not self-declared in
\texttt{therapistInfo}, are not caught by this pass. They are business identifiers rather
than the personal name-and-credentials leak that triggered the work, but they remain in
the corpus and we state so rather than claim a complete scrub.

\subsection{Preference data}
\label{sec:methods:prefdata}

\paragraph{Helpfulness pairs.} The helpfulness pool is PsychoCounsel-Preference
\citep{zhang2026psychocounsel}, 34{,}329 chosen/rejected pairs of therapist-style
responses. We excluded 662 pairs (1.93\%) in which the rejected response carries a
higher safety rating than the chosen response, so that the helpfulness-only arm is not
quietly nudged toward less safe outputs, and 77 pairs whose prompt-plus-completion
exceeds 2{,}048 tokens (6 overlapping the previous exclusion). Pairs are excluded rather
than truncated: a truncated completion corrupts the chosen-versus-rejected comparison the
Direct Preference Optimization (DPO) loss is computed over. The filtered pool is 33{,}596
pairs.

\paragraph{Safety pairs, described accurately.} The safety pool is drawn from
PKU-SafeRLHF \citep{ji2024pku}, harmlessness dimension. From 73{,}907 training rows we
kept 26{,}170 rows whose PKU harm category falls in
\{Physical Harm, Psychological Harm, Mental Manipulation, Violence, Drugs, Human
Trafficking, Sexual Content\} \emph{or} that hit a mental-health keyword bucket
(23{,}214 by category, 5{,}077 by keyword), then required a genuine safety contrast
within the pair (\texttt{is\_response\_0\_safe} $\neq$ \texttt{is\_response\_1\_safe}),
which removed a further 21{,}246 rows (1{,}443 both-safe, 19{,}803 both-unsafe). The
result is \textbf{4{,}924 safety pairs}. The filter is a deterministic documented rule,
not a hand-picked selection, and the pairs are human-annotated rather than
model-generated, which removes the distillation critique.

We audited what this pool actually contains, and the answer changed how we describe it.
Measured against the project's own mental-health keyword buckets, only \textbf{11.8\%}
(582 of 4{,}924) of safety-pair prompts match any bucket; measured against a broader
independently written list, \textbf{4.9\%} (240 of 4{,}924). The remainder were admitted
on PKU harm category alone and are generic-harm content --- verified examples include
concealing an affair from a spouse, rendering an opponent unconscious in mixed martial
arts, and making a dog more aggressive. The frozen evaluation suite, by contrast, is
entirely self-harm, crisis and manipulation in a counselling frame. We therefore
\emph{withdraw} the description of these pairs as mental-health-relevant, which appeared
in earlier project documents, and describe them as \emph{PKU-SafeRLHF, harm-category
filtered, 11.8\% mental-health keyword coverage}. The question this experiment can answer
is correspondingly narrower and is stated as such throughout: whether general-harm safety
preference data \emph{transfers} to therapy-domain adversarial prompts.

Note also that ``chosen'' in these pairs means only the safer of the two responses under
PKU-SafeRLHF's own rubric. It is not a certified exemplar of good crisis practice. Spot
checks found crisis examples appropriately contrastive and at least one
manipulation-tactics example weak.

\paragraph{Matched data volume.} B2 and T both train on 19{,}924 preference pairs: the
same total, the same number of optimiser steps (1{,}246 at effective batch 16), and the
same hyperparameters. Only composition differs. Without this, any T effect would be
confounded with the amount of preference data rather than its type. Both counts, and
content-hash identifiers for every sampled pair, are written at run time to a per-run
data manifest. The training script asserts that the three DPO configurations are
byte-identical on every field except arm label, data composition and preference
direction.

\paragraph{DPO setup.} We train DPO \citep{rafailov2023dpo} on top of the B1 adapter.
Two implementation details were verified against the installed library source rather
than assumed. First, \texttt{PeftModel.from\_pretrained} defaults to
\texttt{is\_trainable=False}; without an explicit override, DPO would have trained
nothing and both arms would have returned B1 unchanged. Second, with no new
\texttt{peft\_config} and \texttt{ref\_model=None}, TRL clones the current adapter into a
frozen reference adapter, so the DPO reference policy is B1's own distribution --- the
intended continuation semantics rather than a custom hack. All three DPO arms use
$\beta = 0.3$, learning rate $5\times10^{-6}$, one epoch, sigmoid loss, and precomputed
reference log-probabilities.

\paragraph{Why $\beta$ is 0.3 and not 0.1.} Our first two B2 runs used $\beta = 0.1$ and
both produced reward statistics that looked excellent and generations that were
degenerate: final reward margins around 8.3 with reward accuracies of 0.975--1.0, and 4
of 8 held-out sanity prompts showing verbatim phrase loops, a fully duplicated response,
or the model fabricating and continuing its own \texttt{User:} turns. Reward statistics
alone would have shipped that checkpoint; the generation check caught it. We raised
$\beta$ to 0.3 as a single-variable change applied identically to B2, T and T\_ctrl, and
held everything else fixed. The degeneracy check is repeated on every DPO run.

\paragraph{T\_ctrl, and the exact limit of what it controls for.} Because the safety
pairs come from a different corpus \emph{and} a different domain than the helpfulness
pairs, any T advantage is equally explained by ``adding roughly 25\% out-of-domain
preference data induced a diffuse caution prior'' as by ``safety preferences were
learned'' --- and the attack-success rubric credits any refusal as a successful defence
on the non-crisis attack categories, so a caution prior scores well without any
safety-specific learning. T\_ctrl holds the corpus, the rows, the prompts, the register
and the volume fixed and varies only the preference direction, taking the chosen response
from PKU's helpfulness annotation (\texttt{better\_response\_id}) instead of its safety
annotation (\texttt{safer\_response\_id}). It draws the identical 15{,}000 helpfulness
pairs as T, guaranteed structurally by using the same seed over the same pool, and
verified at launch by comparing sampled pair identifiers.

The control is weaker than it looks and we state the limit rather than the intent:
\textbf{T\_ctrl differs from T on 776 of 4{,}924 safety pairs (15.8\%), so it bounds the
safety-direction effect rather than isolating it.} On the other 4{,}148 rows (84.2\%) the
safer response and the better response are the same, so T\_ctrl trains on the identical
pair. It still detects the case where T's advantage comes entirely from adding
out-of-domain preference data. We chose this over drawing contrast rows from the 21{,}246
discarded rows, where ``better'' among two unsafe responses would mean training toward
unsafe.

\subsection{The B3 guardrail baseline}
\label{sec:methods:b3}

B3 is an artefact, not a declaration. A script reads B2's generation file, screens each
(conversation, response) pair with \texttt{beaver-dam-7b} \citep{ji2023beavertails}
pinned to revision \texttt{3a5b7088...}, and where any of the model's 14 harm categories
exceeds probability 0.5 replaces the delivered assistant turn with a fixed decline that
signposts to a general practitioner and a crisis line. Nothing is retrained and no
generation pass is repeated, so B3 shares B2's prompts, batches and decoding
byte-for-byte; the arms differ only by the filter. Every B3 record preserves the
underlying B2 response verbatim. The filter block --- threshold, flag rule, categories
and the exact replacement string --- is pinned in configuration, carries
\texttt{do\_not\_tune\_after\_seeing\_results: true}, and its SHA-256 together with the
replacement text's SHA-256 is written into every B3 output header. B3 is reproducible
from that configuration plus B2's generations.

We record one property of this baseline before reporting any number: the filter flags its
own replacement text, so B3 is not a fixed point under a second filter pass. Rewriting
the replacement to evade the classifier would be tuning the arm to the instrument, so we
did not.

Because a single operating point invites the objection that we chose a weak baseline, we
also sweep the threshold. The filter stores its full 14-category probability vector for
every screened item, and every consequence of a fire is deterministic and pre-registered,
so the entire attack-success/over-refusal frontier for thresholds at or below 0.5 is exact
arithmetic over two files: no model is loaded and no judge is re-run. The frontier cannot
show what a judge would have said about a response that a lower threshold would have
replaced, because no such response exists; that is a property of the arm, not an
approximation. The pinned operating point was fixed before the sweep was produced and was
not changed by it.

\subsection{The frozen evaluation suite}
\label{sec:methods:suite}

The evaluation suite contains 300 items in five categories of 60: \texttt{prefilling},
\texttt{persona}, \texttt{many\_shot}, \texttt{crisis\_adjacent} and
\texttt{benign\_sensitive}. It was frozen on 2026-07-31 at 01:22:46 +09:00 with SHA-256
\texttt{e14c3a24184d01cbf31bbcfa42be03104ae07b0bea1132bc5b08a177645b6689}, recomputed
independently at freeze time. Any evaluation whose suite hash differs is not reported.
After the freeze no item may be added, removed or edited; deficiencies found later are
reported as limitations, never fixed by changing the instrument. The suite is never
trained on, and the SFT training script raises rather than training if the training path
resolves under the red-team directory.

\paragraph{Construction protocol.} The taxonomy was fixed first, from the project
contract, and no category was added, renamed or split. Each category was mapped to a
published attack family before any item was written: prefix-continuation attacks for
\texttt{prefilling} \citep{andriushchenko2025adaptive,qi2025safety,vega2023priming},
persona and roleplay framing for \texttt{persona} \citep{shah2023persona,shen2024dan},
in-context normalisation for \texttt{many\_shot} \citep{anil2024manyshot,wei2023jailbroken},
and contrast-set over-refusal probes for \texttt{benign\_sensitive}
\citep{rottger2024xstest,cui2024orbench}. All 300 items were written from scratch; the
technique families come from the literature, the text does not. Items were authored
individually rather than generated combinatorially, because near-duplicate attacks
inflate apparent robustness, and topic, framing, register, length and technique variant
were varied within each category. A harm-content ceiling was enforced: no item contains
method, means, lethality, dosage or step-by-step self-harm content, and prefilling
prefixes stop before any such content, since supplying it is precisely the failure being
measured. Every item carries a one-line expected-safe-behaviour specification written at
authoring time. The build is deterministic and re-running it reproduces the same hash. A
schema validator enforces field presence, unique identifiers, strict user/assistant
alternation, the absence of any system message (the harness prepends the pinned system
prompt itself), and the per-category message-structure contract.

\paragraph{\texttt{crisis\_adjacent} is not an attack category.} It measures whether the
model performs the correct behaviour, specified positively against a cited clinical
guidance rubric rather than author judgment, so that the category is falsifiable. The
seven clauses cover staying engaged and not terminating or bare-refusing
\citep{nice2022ng225}; asking directly about ideation, intent, plan and access to means
when risk is indicated \citep{posner2011cssrs,dazzi2014asking}; checking rather than
assuming where a disclosure is ambiguous; signposting proportionate to acuity
\citep{nice2022ng225,who2016mhgap}; supporting means restriction and collaborative safety
planning where appropriate \citep{stanley2012safetyplanning}; never supplying method,
means or comparative-lethality information and never depicting suicide as a solution
\citep{who2023safemessaging}; and neither promising unconditional secrecy about imminent
risk nor abandoning the user for asking. Failure has two limbs: (a) an unsafe response, or
(b) a failure of required behaviour --- no signposting where acuity demands it, bare
refusal, conversation termination, a hotline dump with no engagement, or assuming crisis
in an ambiguous item without checking. Both limbs are needed, because a blank refusal is
harmless to a content classifier and still wrong. Items span four acuity bands
(approximately 14 imminent, 20 acute non-imminent, 14 ambiguous, 12 lower-acuity items
where correct behaviour is \emph{not} to escalate).

\paragraph{\texttt{benign\_sensitive} supplies the counter-metric.} Every item is a
contrast-set item in the XSTest sense \citep{rottger2024xstest}: surface features overlap
with genuinely unsafe prompts (suicide, self-harm, overdose, medication, restriction,
intrusive thoughts) while intent does not. No item contains risk to the user and none
requests harmful content. Over-refusal counts when the model refuses, deflects with a
bare referral in place of engagement, answers a non-crisis prompt with a crisis-line
script, moralises instead of helping, or replies with content-free boilerplate.
Suggesting professional support \emph{in addition to} substantive engagement is not a
failure; it fails only when it replaces the answer. Without this category a model that
refuses everything would score perfectly on attack success.

\paragraph{Leakage audit.} Before the freeze we ran an automated audit of all 300 items
against all 43{,}863 records in the five processed training files
(\texttt{sft\_train} 2{,}305; \texttt{sft\_esconv} 910; \texttt{sft\_counsel} 1{,}395;
\texttt{pref\_safety} 4{,}924; \texttt{pref\_helpful} 34{,}329). Text was normalised
(NFKD, lower-cased, punctuation stripped, whitespace collapsed) and system messages were
excluded, since every corpus carries the identical pinned prompt and would otherwise
match trivially. Results: \textbf{0} exact normalised full-message matches for messages of
at least 8 words; \textbf{0} shared contiguous 12-word spans; maximum word-5-gram Jaccard
similarity between any eval item and any training record \textbf{0.1034} (mean 0.0150),
with zero items at or above 0.30. Internal near-duplication within the suite reached a
maximum pairwise Jaccard of 0.1014 (mean 0.0177), with no pair at or above 0.40. Below the
8-word threshold, three one-word demonstration turns collide with ordinary training
utterances (``yes'', 78 collisions; ``sure'', 2); these are filler-token collisions, not
item leakage, and we report them rather than suppress them. A repeat check after the
data-provenance scrub found 2 raw string matches, both the single token ``Yes.''.

One item was rewritten \emph{before} the freeze as a result of this audit:
\texttt{benign\_sensitive\_035} shared a 12-word span with a CounselChat-derived prompt in
the helpfulness pool and was rewritten from scratch, preserving its function (a minor
seeking confidential access to mental health support). The rewrite is recorded in the
suite manifest rather than quietly patched. The highest remaining similarity, a 5-gram
Jaccard of 0.103, is the level expected from ordinary English shared within one domain.
Category overlap between training and evaluation is intended; item overlap is not, and
there is none.

\subsection{Generation protocol}
\label{sec:methods:generation}

One pinned configuration governs decoding for every arm, and the harness copies the whole
block into every output file so the settings travel with the data. Decoding is greedy
(\texttt{do\_sample=false}, one beam), because the headline claim is a paired comparison
over a fixed prompt set and the reported uncertainty comes from bootstrap over prompts
and from training seeds; adding sampling noise would inflate variance without adding
information. Maximum new tokens is 512. Generation batches are size 8 with left padding
and length-sorted batching; the harness includes a check that batched output matches
batch-size-one output for the same prompts. Raw generations are never overwritten: the
script refuses to write over an existing file and versions instead.

Qwen2.5-7B-Instruct ships a generation configuration that silently applies sampling with
\texttt{repetition\_penalty=1.05}. We overwrite the generation configuration explicitly
and record the effective values. We set \texttt{repetition\_penalty} to \textbf{1.05},
the model's own shipped value, after measuring a decoding pathology: at 1.0 the SFT
checkpoint degenerates into sentence-level loops on 44 of 300 suite items (14.7\%),
against 1 of 300 for the base model. At 1.05, degeneration falls to 3.0\% of items by a
strict exact-sentence-repeat criterion and 6.0\% by a looser $n$-gram criterion,
concentrated in \texttt{prefilling} (6.7--15\%) and \texttt{persona} and near zero in
\texttt{crisis\_adjacent}. It is reduced, not eliminated, and it reproduces on the clean
retrained checkpoint. Of 7 degenerate attack-category items, 4 scored unsafe and 3 safe
against a 54.6\% base rate, so we found no aggregate verdict bias, but we report the
residual rate as a limitation. Any run generated at a different penalty is superseded and
is not used.

For \texttt{prefilling} items the attacker supplies the opening of the assistant turn.
The harness detects the trailing assistant turn and continues it rather than opening a
new one. It saves both the continuation alone and the full delivered turn; judges see the
full turn, because the attack succeeds if the turn as delivered is harmful.

\subsection{Judges, and why their independence is mandatory}
\label{sec:methods:judges}

\paragraph{The independence requirement.} The mechanism that \emph{filters} for B3 must
never be the mechanism that \emph{judges} attack success. If they were the same, the
filter would remove exactly what the judge looks for, B3 would score near-zero attack
success by construction rather than by merit, and the central comparison would be a
tautology. The scoring harness enumerates every judge whose role is the attack-success
judge and raises on any collision with the filter's mechanism identifier, comparing model
identity rather than prompt --- a different prompt on the same weights is the same
mechanism. Negative controls for this guard are exercised in the test suite, including
against a different revision of the same model. During development the harness refused to
score any arm because an earlier configuration violated this rule; we treat that refusal
as the guard working.

\paragraph{Two safety judges, not one.} A harm-content classifier cannot assess
\emph{correct crisis behaviour} or \emph{wrongful refusal}: a blank refusal is harmless
and often wrong. The three attack categories and \texttt{crisis\_adjacent} therefore route
to different judges with deliberately opposite refusal semantics.

\paragraph{Judge decoding is deterministic.} The prompted judges never sample. Each
generates a short structured analysis greedily, the analysis is truncated at its own
verdict stem, and the label is then chosen by comparing the log-probability of the first
token of each allowed label at a fixed answer position. This cannot produce an
unparseable verdict and yields an auditable margin. A short free-text verdict is recorded
per item for human audit only; it never decides a number.

\paragraph{The judges are pinned.} The judge prompts were pinned on 2026-08-01, before
any arm beyond B1 had been scored. The pin lives in a separate lock file, because a guard
that can be disabled by editing the thing it guards is not a guard; the scoring script
verifies every live prompt file against the lock's hashes and refuses to run on a
mismatch. Defeating the pin requires three deliberate edits, all visible in version
control and all contradicted by the prompt hashes already written into every scored output
on disk. From the pin date, a judge later found to be wrong is reported as a limitation,
not fixed.

\paragraph{Two deterministic scoring conventions.} Both were adopted before scoring any
arm, and both are enforced in code with tests. First, attack items in the three
non-crisis categories whose response was replaced by the B3 filter are scored
\emph{safe} deterministically rather than passed to the judge. The replacement text is
fixed and identical on every fire and the judge's own rubric classes a plain decline as a
successful defence, so the label is known a priori; passing it to the judge anyway
produced 2 clear false positives in 8 replaced attack items, where the judge misapplied
its ``honours a format constraint'' clause to signposting. That error is structurally
asymmetric --- T has no filter and emits no replacement text --- so it would have inflated
B3's attack-success rate only, flattering our own treatment. Applying the rubric's stated
rule removes the asymmetry without editing the judge prompt, so the measured agreement
figure stands. \textbf{This convention reduces the measured B3-versus-T gap.} We adopted
it because it is correct, not because of where it moves the number. Second, the
convention is scoped to the attack-success judge only. A filter-replaced
\texttt{crisis\_adjacent} item continues to score as a \emph{failure}, because under limb
(b) a bare refusal to a person in crisis is a failure of required behaviour; a
filter-replaced \texttt{benign\_sensitive} item is an over-refusal by construction, giving
a deterministic lower bound on B3's over-refusal. The scoring script raises if the
convention's category list is ever extended to either.

\paragraph{Helpfulness.} Helpfulness is a scalar reward from
PsychoCounsel-Llama3-8B-Reward \citep{zhang2026psychocounsel}, run locally at a pinned
revision, reported as the mean over \texttt{benign\_sensitive} and
\texttt{crisis\_adjacent} only. Helpfulness on an item whose correct answer is a refusal
is not interpretable, so the three pure attack categories are excluded.

\paragraph{Provenance gating.} A run is marked as a paper number only if all of the
following hold: the generation header flag is set, filter/judge independence passes, the
judges are pinned, and the adapter re-hashed at scoring time matches the one recorded at
generation time. An earlier version of the harness printed ``paper number'' for an
unpinned, independence-violating run; that failure would have put a circular number in the
main table, and the conjunction gate exists because of it.

\subsection{Judge agreement: what was measured, and against whom}
\label{sec:methods:kappa}

Every number in this paper depends on automatic judges, so we report their agreement. We
also report, plainly, who produced the reference labels, because we got this wrong once.

\paragraph{Correction of a provenance error.} Every Cohen's $\kappa$ we measured up to
2026-08-01 was computed against reference labels produced by a large language model agent,
stored in a field named \texttt{human\_label}. Earlier internal documents described these
as ``hand-labelled''. \textbf{That description was wrong.} All such figures are
\emph{inter-model agreement} --- one prompted Qwen judge scored against a different
model's labels --- and shared model biases plausibly inflate them. They do not satisfy a
requirement for human validation. We corrected the record rather than amending it
quietly, renamed the offending field, and made every label record carry an explicit
boolean for whether the labeller was human, with scoring raising rather than defaulting
when it is absent.

\paragraph{Inter-model agreement (measured).} On held-out sets disjoint from any set used
to tune the corresponding prompt: the attack-success judge (behavioural rubric v3) reached
$\kappa = 0.521$, 95\% CI $[0.29, 0.76]$, recall $0.55$, precision $1.00$ ($n=36$); the
crisis behaviour judge (v3) reached $\kappa = 0.583$, 95\% CI $[0.22, 0.83]$ ($n=24$); the
over-refusal judge (v3) reached $\kappa = 0.074$, 95\% CI $[-0.22, 0.41]$ ($n=32$,
judge-stratified), which reweights to $0.069$ at the natural base rate with precision
$0.20$, and its predecessor (v2) reached $\kappa = 0.077$ raw and $0.038$ reweighted with
precision $0.14$. For comparison, the QA-moderation classifier we first proposed as the
attack-success judge scored $\kappa = 0.355$, $0.086$ and $0.116$ across three blind sets
and behaved as a topic detector rather than a harm detector: it flagged a reply that
\emph{inverts} a self-harm prefill, a reply that \emph{correctly} triages a plan-tonight
disclosure as an emergency, and a plain refusal. We therefore moved it to the filter role,
which is its natural role as a QA-moderation model and a stronger baseline to beat, and
made the behavioural judge the sole attack-success judge. That swap cost recall
($0.65 \rightarrow 0.55$), so attack-success rate is a conservative lower bound in every
arm.

\paragraph{Over-refusal is measured by human labels, not by a judge.} The over-refusal

\subsection{Endpoints, estimator and statistics}
\label{sec:methods:stats}

\paragraph{Endpoint split.} The \textbf{primary endpoint} is attack-success rate over the
180 non-crisis attack prompts (\texttt{prefilling}, \texttt{persona},
\texttt{many\_shot}), scored by one judge under one refusal convention, in which a refusal
is a successful defence. \texttt{crisis\_adjacent} is a declared \textbf{co-primary},
reported separately and never pooled with the primary. We split them because pooling was
incoherent, not merely noisy: the crisis category is scored by a different judge against a
positively specified clinical rubric in which a refusal is a \emph{failure}, the opposite
convention, so a pooled rate averages items where refusing scores 1 with items where
refusing scores 0. Pooling also let the two deterministic conventions of
Section~\ref{sec:methods:judges} --- forced-safe on filter-replaced attack items,
forced-failure on filter-replaced crisis items --- partially cancel inside one headline
number, so neither the number nor its provenance would have been explicable. On a
development fixture, a single pooled 25\% rate concealed a 0.00\% primary rate and a 100\%
crisis rate. The split has a real cost, stated in advance: the primary endpoint fell from
240 pooled items to 180, raising the minimum detectable effect by roughly
$\sqrt{240/180} = 1.15\times$. We accepted that, because a well-powered test of an
incoherent quantity is worth less than a slightly weaker test of a coherent one. The
filter-attributable versus model-generated decomposition of B3's failures is promoted to a
reported primary quantity.

\paragraph{Estimator.} For each prompt we take the \textbf{per-prompt seed mean}: the
fraction of the three seeds on which that prompt failed, a value in
$\{0, \tfrac13, \tfrac23, 1\}$, giving one observation per prompt. This choice is forced
by an internal consistency requirement. The mean over prompts of the seed mean equals the
mean over seeds of the per-seed rate exactly, by linearity, so the table figure and the
headline figure are the same number by construction. The majority vote we used first does
not have this property: it maps a per-prompt failure probability $p$ to $3p^2 - 2p^3$,
shrinking each arm by a different, $p$-dependent amount, so the paper would have printed
two different values for the same quantity and the discrepancy would have been
arm-dependent. Pooling all seed-prompt pairs into one test would triple-count each prompt
and is deliberately not done.

\paragraph{Primary test.} A two-sided paired permutation (sign-flip) test on the
per-prompt differences, 20{,}000 permutations with a fixed seed, with the $+1$ correction
that counts the observed assignment as one permutation. It is distribution-free and valid
for the non-binary seed-mean outcomes, where McNemar's test does not apply. Zero
differences are retained: they contribute nothing to the statistic under the sign-flip
null but do count toward $n$, which is the conservative treatment. We retain exact
(binomial) McNemar per seed as a robustness check, where outcomes are genuinely binary,
and exact rather than $\chi^2$ because discordant counts can be small. Seed variance is
reported separately as a robustness check, never as the primary $n$; with three seeds the
across-seed interval uses the $t$ distribution with 2 degrees of freedom.

\paragraph{Confidence intervals.} Percentile bootstrap over the prompt set, 10{,}000
resamples, with the \emph{same} resampled prompt identifiers applied to every arm in every
replicate, so the pairing that makes the comparison valid survives resampling. Resampling
arms independently would destroy the pairing and inflate the interval on the difference.

\paragraph{Attenuation correction, and the scale the threshold lives on.} The
attack-success judge has precision $1.00$ and recall $0.55$, so an arm whose true failure
rate is $p$ is measured at $r\,p$ and a true difference $D$ is observed as $r\,D$. A true
10-point reduction --- our pre-registered minimum meaningful effect --- would therefore be
measured as 5.5 points and would have failed our own threshold. We resolved this by fixing
the units rather than lowering the bar: the 10-point threshold is on the \textbf{true}
scale, the primary reported effect is attenuation-corrected as
$\text{true} = \text{observed}/\text{recall}$ per arm, and the raw observed effect is
reported beside it, always. Because the recall interval is wide, the correction is reported
as a range across each arm's 95\% recall interval rather than as a point, and the harness
flags the case where the implied true rate exceeds 1, which signals the constant-recall
model being pushed past where it holds rather than a large effect. The correction refuses
to run off recall estimated against model-produced labels; if only such labels exist, the
harness reports the raw observed effect and states that the correction is pending.

We also withdraw, as false, a claim asserted in three earlier project files and printed
into the headline sentence: that the judge's under-count is identical across arms and does
not bias the contrast. Our own pinned records state that this judge under-counts terse
arms, and the arms differ in terseness, so equal recall across arms is an assumption
rather than a measurement. A recall-sensitivity sweep replaces the claim. It quantifies
the risk: at a 40\% true rate with per-arm recalls of 0.65 and 0.45, a \emph{zero} true
effect is measured as an 8-point reduction --- most of our threshold, manufactured
entirely by differential measurement. The deterministic forced-safe convention removes the
largest known source of differential recall (the filter's fixed decline text, exactly the
terse output the judge scores differently); what remains is unquantified until per-arm
human recall estimates exist.

\paragraph{Power, computed before any arm was scored.} A Monte Carlo simulation over the
exact shipped procedure (per-prompt seed mean, paired sign-flip permutation test,
$\alpha = 0.05$, 3 seeds, 4{,}000 simulations, heterogeneous per-prompt probabilities)
gives power against the pre-registered effects of \textbf{0.95} for the primary endpoint
($n=180$, $-10$ true points, 40\% baseline), \textbf{0.50} for the crisis co-primary
($n=60$, $-10$ true points), and \textbf{0.20} for over-refusal ($n=60$, $+5$ points).
Minimum detectable effects at 80\% power are 7.9 true points for the primary endpoint at a
40\% baseline (7.5 at a 25\% baseline), 14.4 for the crisis co-primary and 13.9 for
over-refusal. The binding constraint is the instrument, not the sample size: recall 0.55
attenuates every effect by roughly 45\%, and no additional seeds can help, because pairing
is across prompts and the prompt set is frozen.

\paragraph{Over-refusal is reported descriptively.} With 60 benign items, power to detect
the 5-point tolerance is 0.20 and the bootstrap 95\% half-width on the paired difference is
4.6--6.6 points \emph{even at a true difference of zero} (a second simulation, sweeping the
baseline over-refusal rate from 10\% to 35\%, gives 5.3--8.5 points). Either way it is
wider than the tolerance itself. The suite is frozen and items cannot be added. We
therefore report over-refusal as
a point estimate with a 95\% interval; evaluate the 5-point tolerance against the point
estimate, because applying it to the interval's upper bound made it unmeetable at any true
value; phrase the bounded-cost clause as ``no evidence of a large over-refusal increase''
rather than as a criterion passed; and emit an automatic precision warning whenever the
interval is wider than the tolerance. The headline sentence is worded ``changing
over-refusal by $Z$ points (95\% CI $[\text{lo}, \text{hi}]$)'' rather than ``increasing
over-refusal by at most $Z$ points'', because the original wording implied a guarantee the
interval does not provide.

\subsection{Pre-registration}
\label{sec:methods:prereg}

We wrote the pre-registration on 2026-07-31, after freezing the evaluation suite and
training B1, and before any evaluation that could produce a paper number. It fixes the
hypothesis and its direction (we predict lower attack success for T than for B3, and a
result in the opposite direction is reported as such), the minimum meaningful
attack-success reduction (10 percentage points), the maximum acceptable over-refusal
increase (5 percentage points), the primary test, the judge configuration, the suite hash,
and the matched training volume. It also fixes, in advance, what would falsify or
complicate the claim, so that a null result is a finding rather than a shrug: if we
observe a 3-point reduction, we report that we powered for 10 and observed 3.

The pre-registration carries seven dated revisions, each made before the results it could
have affected existed, each retaining the superseded text verbatim, and each stating its
direction of effect on our own hypothesis. Revision~1 added a second attack-success judge
after blind validation put the original at $\kappa = 0.355$ with 17 of 29 genuine attack
successes missed. Revision~2 withdrew that union and swapped the roles, because the added
judge shared a backbone with the declared filter and the harness correctly refused to
score anything; it states the resulting recall loss and the lower-bound consequence.
Revision~3 introduced the deterministic forced-safe convention for filter-replaced attack
items, and \emph{reduces} the measured gap in our favourite direction's disfavour.
Revision~4 moved over-refusal to human labels. Revision~5 added the T\_ctrl control arm and
withdrew the description of the safety pairs as mental-health-relevant, reframing the claim
as a transfer question; it exists to make our own claim falsifiable. Revision~6 fixed the
attack-success threshold to the true scale, made the primary effect attenuation-corrected,
deleted the false identical-under-count claim, and recorded the endpoint split and its
$1.15\times$ cost in minimum detectable effect. Revision~7 made over-refusal descriptive
rather than a passed test and reworded the headline sentence. We list them here because a
revision that is not visible is not a pre-registration.

\subsection{What this design cannot measure}
\label{sec:methods:designlimits}

Two limits are properties of the design, fixed before results existed, and we state them
in Methods rather than discovering them later.

First, \textbf{this design cannot resolve a 5-point over-refusal difference.} The frozen
suite contains 60 benign items; power against the 5-point tolerance is 0.20 and the
bootstrap half-width exceeds the tolerance even when the true difference is zero.
Additional seeds cannot help, because pairing is across the 60 prompts and the prompt-level
$n$ is fixed. A point estimate inside the tolerance is therefore weak evidence of a bounded
cost, and we label it as such.

Second, \textbf{attack-success rate is a conservative lower bound.} At recall 0.55 roughly
45\% of genuine attack successes go uncounted in every arm. Absolute rates are lower
bounds, observed differences are attenuated by approximately the recall factor, and equal
recall across arms is an assumption we do not have the measurements to defend --- which is
why the attenuation correction is per-arm and why the recall-sensitivity sweep is reported
rather than a single corrected number.

A third limit is worth naming here because it is invisible to every metric we report:
B1's fabricated self-disclosure and its terse under-response sit outside the frozen attack
taxonomy, outside PKU-SafeRLHF's harm categories, and outside the QA-moderation
classifier's taxonomy. All arms inherit them and no number in either results table
penalises them. This is a limitation of the evaluation, not a difference between arms.

\subsection{Ethics, licensing and release}
\label{sec:methods:ethics}

This is a research prototype for wellness-support dialogue. It is not a treatment, it was
not evaluated with human participants in a care setting, and we make no claim of
therapeutic efficacy for any condition. The evaluation rubric for crisis-adjacent items
follows published clinical guidance so that the category is falsifiable; it does not
constitute clinical advice and the guidance documents are cited as the source of the
scoring criteria, not as an endorsement of the model.

The red-team suite contains adversarial prompts about self-harm and suicide. We enforced a
harm-content ceiling at construction: no item contains method, means, lethality, dosage or
step-by-step self-harm content, and prefilling prefixes stop before any such content. The
suite file itself is not committed to the repository; the deterministic builder and the
per-item source modules are, so the suite is reproducible and the freeze hash is
verifiable.

CounselChat is not anonymised, and Section~\ref{sec:methods:scrub} documents the identity
scrub we applied after finding memorised clinician identity in generated text, together
with its residual limitation. We report the incident because a therapy-support model
emitting a named real clinician's identity in response to a crisis prompt is a finding
about scraping public professional forums, and it was caught only by reading generations by
hand.

PsychoCounsel-Preference and PsychoCounsel-Llama3-8B-Reward are licensed CC-BY-NC-4.0
(non-commercial). Every checkpoint trained or scored with them inherits that restriction.
We state it here and it travels with any artefact we release. We release code,
configurations, judge prompts, the
suite builder and the pre-registration with its revision history; we do not release
training data, generations or checkpoints from this repository.
